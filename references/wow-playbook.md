# Wow Playbook — 让人「眼前一亮」的首屏

目标：观众在 2 秒内记住这一屏。本文件是 One-Click Replica 的**视觉验收标准、3D 方案库和实测教训**。工程 QA 通过不等于有 wow；wow 只由截图判断。

## 1. 先定 Signature Moment（只选一个）

一屏只给一个记忆点，其余元素为它服务。

| Moment | 做法 | 3D variant | 适合 |
| --- | --- | --- | --- |
| 玻璃主体 | 折射 + 色散的透明物体，背后有光源可折射 | `glass-knot` | 工作室、AI、金融科技、高端品牌 |
| 液态金属 | 噪声位移的高反射球，随指针轻微形变 | `liquid-blob` | 音乐、时尚、潮流、活动页 |
| 环绕卡片 | 作品/产品卡片绕主轴漂浮 | `orbit-cards` | 作品集、电商、SaaS 功能展示 |
| 巨型字 + 景深 | 超大衬线标题压在 3D 物体之前/之后 | 任一 + 调 `styles.css` | 编辑式杂志感 |
| 滚动变形 | 滚动驱动相机/材质，首个过渡改变布局关系 | 需扩展（见 §4） | 产品叙事 |

选择依据：参考的主体是什么质感，就选对应质感；参考没有 3D 时，3D 只能是「把参考的主形状立体化」，不要凭空加一个无关物体。

## 2. 视觉验收（Wow Gate）

对**最新桌面+手机截图**逐项打 0–2 分，总分 ≥ 14/20 且无 0 分项才可标 `accepted`；否则 `needs-polish` 并写出下一轮要改的两件事。

1. **主体辨识**：1 秒内能说出画面主体（不是一堆装饰）。
2. **尺度对比**：标题与主体至少一个大到有压迫感（标题行高 ≥ 视口高度 12%，或主体 ≥ 视口宽度 35%）。
3. **材质可信**：高光、折射、阴影来自同一个光向；没有「发黑」「塑料」「漂浮的贴图」。
4. **一屏完整**：首屏内标题、副标、CTA 全部可见，主体不被裁掉半个（除非是刻意出血，且写进规则）。
5. **色彩克制**：不超过 1 主色 + 1 辅色 + 中性色；强调色只出现在 2–3 处。
6. **字体权威**：显示字体有性格（衬线/压缩无衬线/等宽之一），与正文字体形成对比；回退字体不算通过。
7. **负空间**：文字块与主体之间有明确呼吸，不互相遮挡（刻意叠压须可读）。
8. **节奏**：首个过渡（marquee/网格/分栏）改变了布局关系，而不是重复同一种卡片。
9. **手机重排**：主体仍是焦点，标题不超 4 行，CTA 在拇指区；不是桌面缩小版。
10. **动效克制**：只有一个主动效（指针倾斜 / 缓慢自转 / 滚动）；`prefers-reduced-motion` 下为静态终态。

## 3. 3D 实测教训（来自本仓库模板的真实迭代）

这些都是首轮实现真的出现过的问题，写进检查清单：

- **透明材质放在深色页面会发黑。** 透射只能折射场景里存在的东西。必须在主体后放柔和的加性发光贴图（不是硬色块——硬色块会直接被看到）。`GlassBackdrop` 已内置。
- **按视口计算位置与尺寸，不要写死世界坐标。** 写死 `x=1.9` 在 4:3 视口会把主体裁掉；用 `useThree().viewport` 推导（`Placement` 已内置）。
- **CSS 的 `ch` 单位跟随当前元素字号。** 把 `max-width: 20ch` 放在 16px 的容器上，再放进 188px 的标题，会把一行字挤成五行并把 CTA 挤出首屏。大标题容器用 `vw`/`px`，标题字号用 `min(vw, vh)` 双约束。
- **Google Fonts 在部分网络下不可达**，回退字体会让「字体权威」直接失分。字体用 `@fontsource` 打进包。
- **WebGL 首次编译需要数秒**（透射材质尤其慢）。截图前等 `canvas[data-ready=true]` 再静置 ≥3s，否则拍到的是 CSS 回退图，会误判。`capture.mjs` 已处理。
- **hero 高度由内容撑开时，铺满 hero 的 canvas 也会被撑高**，主体随之下沉。先保证文字块能放进一屏。

## 4. 进阶 3D 食谱（按需，一次只加一个）

| 需求 | 做法 | 预算 |
| --- | --- | --- |
| 滚动驱动 | 用 drei `ScrollControls` 或原生 `scroll` 事件写入一个 `progress` ref，在 `useFrame` 里插值相机 z / 材质 `distort` | 不得移动版面关键文字 |
| 加载真实模型 | `useGLTF` + Draco；在 `scene_contract.asset_license` 写来源和许可；`<Suspense>` + CSS 回退 | 模型 ≤ 1.5MB，手机用低模 |
| 后期（泛光/噪点） | `@react-three/postprocessing` 只加一个 Bloom；手机关闭 | 掉帧即回退 |
| 粒子 | 单个 `Points`，≤ 2000 点，手机减半 | 不与自转、指针拖尾叠加 |
| 背景 Shader | 全屏三角形 + `uTime`/`uPointer` uniform | 帧耗时 < 4ms |

任何扩展都要先写 scene contract（见 [3D and Motion Playbook](3d-motion-playbook.md)），并保留 CSS 静态回退。

## 5. Pinterest 参考的获取（Claude Code / Codex 通用）

Pinterest 常有登录墙和反爬，按顺序尝试，**任一步失败就改要用户截图，不要硬绕**：

1. 用户直接给截图或下载好的图 → 最优，直接作为 reference。
2. 给 Pin 链接 → 用浏览器工具打开，读取 `meta[property="og:image"]`；把路径里的 `/236x/` `/474x/` `/564x/` 换成 `/originals/` 取大图（需用户同意下载，说明文件名与来源）。
3. 给的是搜索/看板链接 → 只能当候选线索，请用户指定一个 Pin；不得写成「已观察设计」。

只取**关系**（构图、比例、层级、色彩角色、动效），不复制品牌文案、商标、图片素材。写进 Replica Card 的 `adaptation_boundary`。

## 6. 迭代顺序（每轮重新截图并查看）

1. **Structure**：主体尺度与位置、标题宽度与换行、首屏是否放得下、手机重排。
2. **Material**：光、折射、色彩、字体、素材一致性。对照 §2 找最低分的两项。
3. **Behavior**：指针/触控响应、加载回退、reduced-motion、键盘焦点。

每轮在 `.ui-design/` 记录：改了什么、对应 §2 哪一项、前后截图 ID。
