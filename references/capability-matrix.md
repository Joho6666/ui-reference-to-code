# UI Capability Matrix

Use this matrix to pressure-test a workflow against different information shapes. A landing page alone cannot prove that the skill handles dense product work or stateful interaction.

## Benchmark types

| type | primary pressure | minimum proof | common failure |
|---|---|---|---|
| editorial destination | art direction, rhythm, imagery, mobile re-composition | one hero, one story transition, one responsive crop | beautiful hero with generic downstream sections |
| premium product / configurator | material, scale, state changes, 3D responsibility | one object scene, one selector, one CTA, static fallback | decorative 3D without a product job |
| operations dashboard | density, hierarchy, data states, tables and controls | metrics, chart, activity feed, table, filter state | attractive cards that hide the actual workflow |
| campaign / event | urgency, schedule, conversion and motion | date hierarchy, ticket CTA, agenda or countdown | atmosphere overwhelms action |
| editorial commerce | discovery, comparison, trust and checkout path | category rail, product comparison, purchase path | magazine styling delays the decision |

## Run protocol

1. Pick one type that differs from the last completed project.
2. Record `mode / source / scope / primary pressure` before coding.
3. Build only the shell, hero or first workflow state.
4. Capture desktop and mobile at the same viewport pair.
5. Exercise one real state: filter, selector, menu, form, or hover/touch response.
6. Record `strengths`, `failure`, `repair`, and `next test` in a capability report.
7. Promote a rule to the main Skill only after it survives two different page types.

## Acceptance language

- `proven`: the pressure is visible in screenshots and the interaction works in the tested state.
- `prototype`: the direction is clear but content, real data or secondary states remain provisional.
- `gap`: the page works while the target pressure is still generic or unresolved.

A passing build only proves implementation. A capability is proven by the appropriate visual evidence plus the relevant interaction evidence.
