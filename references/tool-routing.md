# 工具分工与接入

## 先确认当前能力

分别确认浏览器可控页面、技能文件、MCP 实际工具列表，以及项目的依赖清单。已安装、已配置、成功调用、进入项目和实际呈现是不同状态；根据观测结果报告。

技能包提供流程、参考模板与判断标准。浏览器、MCP 和组件库依环境接入；缺少某个可选工具时使用适合任务的替代路径并说明限制。只在当前任务需要时处理安装，不把新技能调用当作批量安装所有工具的授权。

## 设计技能

| 当前问题 | 可用技能与做法 |
| --- | --- |
| 主视觉、作品集构图、字体与留白 | 可选当前环境的 `frontend-design`；先确定视觉与内容主张 |
| 配色、设计系统、具体交互或响应式规则 | 可选 `ui-ux-pro-max`；依其工作流使用 design-system、domain 或 stack 查询，核对结果匹配当前项目 |
| 用户明确点名 `frontend-skill` | 读取该技能；当前安装版本要求显式点名才使用，后续以实际技能指令为准 |
| Semi 组件规范、版本 API 与代码示例 | `semi-design-guide` 配合可用的 Semi MCP |
| 已实现页面的具体 UX / 可访问性问题 | 可选当前可用的界面审查技能，只检查和修复实际改动及相关风险 |

通常选择一项主要设计技能，再补充与实际组件或问题有关的资料。缺少这些技能时，也可按 brief、参考和实际框架继续执行本流程。

## Semi MCP：用文档解决具体组件问题

官方 [MCP / Skills 文档](https://semi.design/zh-CN/start/mcp-skills) 描述了组件文档、代码块和源码查询。实际调用时先发现当前工具 schema，再指定项目需要的版本。

一个典型路径：

1. `get_semi_document` 查询 Input、Tabs、Steps 或当前需要的组件。
2. 文档示例被隐藏且确实需要时，调用 `get_semi_code_block`。
3. API 无法解释行为时，再通过 `get_component_file_list`、`get_file_code` 或 `get_function_code` 查看实际文件和函数。
4. 核对项目框架、React 兼容性、组件与图标引入、主题及相关样式，再实现。

原生静态站可参考这些交互规范并实现语义 HTML；组件实现采用适合当前技术栈的方式。声明使用了 Semi 组件时，项目应确实引入并运行相应组件。

服务器已配置但工具未出现在当前界面时，先核对工具发现机制和已有配置。环境支持时可用 MCP SDK 连接当前已注册的本地服务并查询，沿用实际命令、schema 与模块解析；避免将某台机器的缓存路径写进通用项目。否则使用官方文档，并说明没有通过 MCP 实际查询。

## ECharts：依据数据用途选图

接入前确认：访客要回答的问题、可核对的数据、分类与统计口径，以及图表是否比文字 / 列表清楚。可用数据既包括业务指标，也包括真实的项目分类和关系。

示例数据需明确标注。项目标签交叉计数时说明重复归类；业务流程的示意不赋予未经验证的转化率、效率或收入。

[官方引入文档](https://echarts.apache.org/handbook/zh/basics/import/) 提供按需注册核心、图表、组件与渲染器的接口。对于有构建流程的项目，按需引入并在项目清单中声明版本；简单静态站可采用合适的官方分发包，保留许可证和通知，按实际用途延迟加载。

预留尺寸，处理 resize 和销毁生命周期。为 Canvas / SVG 数据呈现提供文本或表格，以及键盘可用的筛选路径。记录加载方式与体积影响，展示真实用途才引入图表。

## Spline：先确定静态视觉还是实时交互

选择实时 3D 时明确鼠标 / 触屏交互、镜头、页面滚动和加载失败的表现，使用官方导出的资源。对于材质或造型表达，静态图也可能完成视觉目的。

依据 [官方性能指南](https://docs.spline.design/exporting-your-scene/how-to-optimize-your-scene) 检查导出体积、几何、材质、纹理和嵌入数量。按场景采用延迟 / 点击加载、占位图和静态替代，限制交互对页面滚动的干扰。

iframe 文档加载与 GPU 画面实际渲染分别验证。无法看到有效场景时报告观察限制并交付可用替代状态；减少动态效果时保留主要信息。

## 发布工具

当任务包含页面实现和交付时，读取所选托管工具的当前流程。复用已有项目身份，核对受众与本次授权，处理真实的构建及上传步骤。对仅研究、仅本地或只保存的任务交付相应结果。

Node / Python / 包管理器以实际可执行路径为准。遇到打包缺少运行时，确认环境与脚本的 PATH 后修正，避免无依据地重装整个环境。发布凭证仅通过托管工具允许的通道传入。
