# 参考采集与素材

## 根据问题选来源

| 来源 | 适合回答的问题 | 需要提取的内容 |
| --- | --- | --- |
| Pinterest | 首屏构图、排版、材质、短视频动效有什么方向？ | Pin 直接链接、画面与关键状态、外链作者、实际可观察范围 |
| Behance | 整个案例如何讲故事、安排功能与转化区？ | 项目链接、段落节奏、界面样例、作者对交互的说明 |
| Spline | 哪种空间、材质或 3D 交互能表达主题？ | 官方模板或社区文件、作者、授权依据、静态表现、导出方式 |
| Semi Design | 当前组件如何布局、反馈状态、处理交互？ | 对应组件、项目版本、文档 API、需要的示例或源码 |
| Apache ECharts | 怎样清楚表达现有数据或关系？ | 实际数据与口径、适合的图表、选择交互、可访问替代内容 |
| 实际上线产品、用户项目及仓库 | 哪些能力与交互真实存在？ | 可打开页面、项目截图、README、阶段说明及数据来源 |

这些来源可按需组合。Pin 和设计稿的证据应写成“预览 / 概念稿”，实际访问到的上线页面再记录其运行行为。作者声称的动效与自己观察到的动效分别说明。

## 浏览器操作与记录

1. 使用已安装浏览器技能的 TaskSpace、页面和观察接口。Ego 的线上教程与本地技能可能处于不同版本，按本地技能和当前 runtime help 确认 API，保持调用方式一致。
2. 同一用户目标复用同一个代理空间。每轮保存空间 ID、页面标签、当前网址和任务状态；截图失败时在当前空间诊断，遵循其控制权与停止规则。
3. 用语义快照定位内容，用截图判断构图；观察视频或 Canvas 交互时补充关键状态。仅提取与当前决策有关的内容。
4. 页面要求登录或验证时由用户完成。受限来源记录限制，可访问的其他参考继续使用。收藏、关注、评论和发布等账号写入需要用户相应授权。
5. 在结果截图已经查看、需要的浏览器工作已经结束后，再按浏览器技能完成空间清理。

参考表建议字段：

| ID / 来源链接 | 证据类型及观察范围 | 借鉴规则 | 用于哪个区域 | 实现方式 / 难度 | 加载与交互取舍 |
| --- | --- | --- | --- | --- | --- |
| 自行填写实际来源 | 上线页面 / 视频帧 / 概念稿 / 缩略图 / 文档；附未确认事项 | 用一句话解释可迁移的规则 | 对应本项目结构 | CSS、组件、图表或 3D | 桌面、触屏、减少动态效果及替代内容 |

关键词从页面用途、受众和主视觉方向生成，例如企业作品集用 `AI portfolio light editorial website`，有明确参考时优先查看原链接。

## 把参考变成可用素材

为进入项目的素材保留一条记录：来源页面、作者、具体资源、使用位置、使用依据、获取时间、是否已核对、预览或最终资源、是否需署名。优先从官方支持的导出路径取得资源。

Pinterest / Behance 的设计截图通常作为灵感证据；用于产品展示的真实截图应来自对应项目。需要相似构图时，可制作适合本项目的原创视觉。

Spline 官方 [3D Library](https://docs.spline.design/designing-in-3-d/scenes/3d-library) 的说明覆盖库内 3D 模型的免费商业使用。社区文件、网站缩略图和模板附带资源分别核对其实际使用范围；没有足够依据的素材先作为参考，并选择可用的替代素材继续制作。

原型界面、主题视觉和示意数据在界面中保留用户能理解的标注。用户提供的未公开项目需要依据当前公开授权选择展示范围。

## 输出与记录的衔接

参考表是 Reference Board；每条进入实现的重点参考按 [Reference Decomposition](reference-decomposition.md) 补充设计规格。多轮记录及 design-system 的结构统一见 [Visual Translation](visual-translation.md)，避免维护两份不一致的 record 模板。

Figma 稿件作为参考时保留具体节点、稿件属性和导出依据；有权限和工具才能称已读取稿件。仅有网页链接或封面时记录实际可观察范围，不推断组件内部属性。
