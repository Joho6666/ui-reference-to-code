## 实际取舍

1. 先整理完整能力再设计导航：早期页面标题只覆盖视频，用户指出范围后才扩展。下一次在 brief 里提前核对用途及内容清单。
2. 大构图与真实作品共同建立识别度：首屏视觉表达个人方向，项目截图提供具体证据，主题图保留来源标注。
3. 轻量与实时效果分别处理：手部滚动使用图片和 CSS；Spline 场景通过用户操作开启，保留静态替代。
4. 组件规范与实际运行组件分别记录：Semi MCP 已实际查询；原生静态页面没有因此变成 Semi React 项目。
5. 图表有可核对口径：分类数从当前项目标签计算，同一项目可计入多个方向。它表示项目覆盖情况，商业成果须另有证据。

## 下次应提前补齐的环节

- 收敛参考后，用同一份设计记录保持跨轮方向，减少重复采集。
- 逐项核对素材类型和使用依据，包括模板、社区文件及网页预览图的具体范围。
- 截图和语义检查结合。本次本地预览验证了搜索、分类、图表初始化及移动布局；截图中的深色表现与浅色 CSS 不一致，原因尚未确认，因此浅色视觉表现仍需单独核对。
- 在视口变化后重新进入目标位置，复核固定导航与标题的相对位置。
- 获取真实目标数据后再决定是否增加业务图表，优先解决访客理解和浏览问题。

将这些经验迁移到其他项目时，使用新项目的受众、内容、风格和实际技术栈重新选择方案。
