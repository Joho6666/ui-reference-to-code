# 页面检查与交付

## 比较能够证明改动的状态

条件允许时，为相关区域保留修改前后相同视口、滚动位置、配色和交互状态的截图，并实际查看截图。不同状态的画面不能直接用于说明改善。

页面应通过适合该项目的 HTTP 服务或托管预览打开。`file://` 的运行方式可能与部署环境不同；涉及请求、模块或第三方资源时，以实际预览环境核对。

从本轮变动选检查项：

| 改动 | 需要观察的关键状态 |
| --- | --- |
| 首屏 / 导航 | 标题与主要按钮完整、固定导航不遮挡目标内容、跳转位置正确 |
| 排版 / 作品卡片 | 标题换行、长文本与标签、图片区、卡片展开、移动布局 |
| 搜索 / 分类 | 默认、命中、无结果、组合筛选、清空、展开更多、计数与实际列表一致 |
| Tabs / Dialog | 选择状态、键盘移动、内容关联、打开关闭、焦点返回、触屏路径 |
| 图表 | 数据口径、标签和提示、选择行为、尺寸变化、延迟加载、文本或列表替代 |
| 3D / 视频 / 动效 | 实际画面、用户控制、移动滚动、减少动态效果、失败或静态替代 |

适当使用桌面和移动视口；断点附近或特殊横屏在发现相关问题时补查。调整视口后等待布局稳定，必要时重新进入目标位置，避免把旧滚动位置造成的截断误判为正常布局。

## 观察结果的边界

- DOM 快照支持检查文本、语义和可见状态；截图支持检查构图、颜色和裁切。记录各自实际证明了什么。
- Canvas 出现、库可调用或 iframe load，只能证明相应初始化或文档加载。有效图形、交互及数据表达仍需实际观察。
- 图片来源、项目阶段与数据口径也是 UI 的一部分：缩略图、功能示意与真实项目截图分别标注。
- 适合改动的构建、语法、类型和功能检查按项目要求执行；修复后复查受到影响的路径。

## 颜色和浏览器状态异常

截图配色与设计 / CSS 不一致时，检查主题选择、媒体查询、计算样式、扩展注入或浏览器配色设置；将截图现象与已定位原因分别记录。可访问路径下进行对照，保留用户原有配置。

只发现深色截图且原因不清楚时，报告“配色原因未定位 / 浅色视觉待确认”。不要据此声称浅色视觉已验收，或直接覆盖整个设计配色。

## 卡住时恢复

先观察当前页面、控制权及服务状态，再选择有依据的恢复动作。一次截图失败后在当前空间定位，避免连续重复失败调用或新建空间掩盖问题。

用户接管浏览器时遵循该浏览器技能的停止与交还规则。来源受限可继续其他材料；关键视觉验证受限时如实说明，完成仍可执行的实现与检查。

## 交付

研究输出：精选来源、观察范围、适用区域、提炼规则、实现难度和取舍。

实现输出：可见页面或预览、改动及用途、实际检查结果、必要的限制。任务需要发布时，遵循用户范围及适用托管工具的流程，使用已确认的成功 URL；发布过程中失败则报告具体失败环节，并保留可审阅结果。

复盘输出：本轮最有价值的设计决定、发现的真实问题、下一次该提前确认的事情。下一轮从未完成问题推进，避免为展示工具而增加无用途的效果。
